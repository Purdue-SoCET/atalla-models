## 3. Deltas versus the September 27 table

- Bytes loaded/written for Basic and AlexNetSmall match the September rows exactly (traffic is fixed by the tiling plan). ViT Micro traffic rose (113,216 → 121,408 load bytes) because the 2,048-element residual add now runs on the emulator instead of NumPy after the add fix.
- Scheduled packets, dynamic packets, retired instructions and FLOPs are lower than in September (Basic: 1,791 → 1,593 scheduled packets; FLOPs 15,212 → 7,884). Cause: Aman's PR #2 (Oct 29) ported the kernel generators from inline assembly to C intrinsics and pointer loads, so the same work issues fewer instructions, and FLOPs are counted from retired instructions. The sim moved from the April pin to ITaP `main` (vector-register spills, instruction counts) with no datapath change.
- The ViT flash trial, recorded as failing in September, now passes (see section 4).

## 4. Defects found and fixed today

1. **Compiler immediate range** (`aihw-ppci-compiler/ppci/arch/atalla/instructions.py`, `pattern_add_i32_reg_const`): `reg + const` selects `addi_s` for any const below 4096, but the immediate is signed 12-bit, so `+2048` executes as `-2048`. Any multi-tile kernel that bumps a pointer by 2,048 bytes walked backwards and the second tile's store clobbered the scalar stack. Worked around in `kernels/{add,mul,relu}.py` by materialising the stride in a register (`docs/add_kernel_multitile_fix.md`). The compiler pattern bound should be `-2048 <= value < 2048`; to be reported to the compiler team.
2. **Flash SDPA kernel** (`kernels/flash_sdpa_n32d32.c`, `emit_sdpa`): K was DMA'd into scratchpad 0 but read from scratchpad 1 (the 4th `vector_load` argument), giving uniform softmax rows; and V must be stored transposed because the systolic array computes `out[j] = Σ_k a[k]·G[k,j]` with rows loaded as columns. Both fixed; sdpa node cos −0.11 → 0.999987 (`docs/flash_sdpa_investigation.md`). Robust under both the current and the pending lw.vi semantics.
3. **Schedule mode** (`scripts/generate_schedule.py`): `graph_schedule.c` silently dropped layer_norm, gelu and softmax calls; now emitted. Also found that `atalla_cc` rejects `1e-05` and `0.5f` literals, so no previous `graph_schedule.c` ever compiled; floats are now emitted as plain decimals and all seven models' schedules pass `atalla_cc -S`.
4. **Flat-RAM converter overlap** (`functional_sim/merged_in_to_ram_hex.py`): documented, not fixed (sim repo).

## 5. GPT-2 block coverage summary

Blocks are sized for the 32-wide Atalla tiles: N=32 tokens, D=32, 1 head, MLP hidden 128. Attention is written with explicit ops (QKᵀ matmul → scale → + causal mask buffer → softmax → ·V) so every node lowers to an existing kernel; the fused flash kernel is non-causal and is not used here.

- Attention block: all compute on the emulator (15/0/5), cos 0.999999.
- MLP block: all compute on the emulator with the GELU kernel (7/0/2), cos 0.999997.
- Full block: all compute on the emulator (22/0/7), cos 0.999995.
- Schedule mode: 21 kernel calls for the full block (matmul, add, layernorm, gelu, softmax), compiles with `atalla_cc`.
- Remaining gaps (issue #66): multi-head attention, D=768 (real GPT-2 Small) tiling and a multi-tile row softmax, a causal fused attention kernel, embedding/positional/dropout ops, training for these blocks.

## 6. Visual benchmarking workbench (v1)

`bench/workbench.sh` → `http://<this machine's IP>:8765`. Built today on top of the harness.

- **Model and options**: every model in `run_graph.py`, seed, scale, per-model knobs (GELU kernel, SDPA path, add→NumPy threshold), strict gate, tag.
- **Call graph**: the exact FX graph after lowering and tile planning (48 nodes for the GPT-2 block), rendered top-down and coloured by backend. Selecting a node shows op, shape, dtype, phase, the Atalla kernel it maps to (e.g. `matmul → kernels/gemm.py`, `gelu → kernels/gelu_tanh.c`), its tile configuration, DRAM address and the reason for the decision. Inspection runs the real planner without the emulator (0.2 s).
- **Overrides**: force any node to `numpy` (reference), `emulator` (kernel) or `skip` (identity), choose kernel variants; the same JSON drives `run_graph.py --overrides` on the CLI, and the same decision function is used by inspection and execution, so what you see is what runs.
- **Runs**: launched from the UI through `bench/run_benchmark.py`; progress streams per node (cosine, rel-L2, packets, bytes, FLOPs) with live charts; final summary tiles; per-node generated `.c`/`.s` viewer; log viewer; cancel.
- **History and compare**: every run under `docs/baselines/` with provenance; pick two runs for grouped bar charts and overlaid per-layer cosine.
- **Export**: one click writes `output/runs/<run>.xlsx` (a `Run - …` sheet in the tracker's layout) and rebuilds `output/Atalla_Benchmarking_Tracker.xlsx` (Current Baseline rows, Cost Model feature values, one sheet per run, Kernel Status / Model Ops cells updated with measured facts).

Verified today against the live server: inspect → override → run (GPT-2 block, 48 nodes, 10 s) → summary matching the baseline row → export.
